## Config dirs
- **Project dir:** `.omp/` (`CONFIG_DIR_NAME = ".omp"`). (docs/config-usage.md)
- **User/global dir:** `~/.omp/agent/` — NOT `~/.omp/` directly. Named profiles relocate it to `~/.omp/profiles/<name>/agent/` (via `omp --profile`, `OMP_PROFILE`, legacy `PI_PROFILE`). `PI_CODING_AGENT_DIR` relocates the default profile's agent dir; `PI_CONFIG_DIR` changes the user root used by generic helpers. (docs/config-usage.md)
- **Discovery/precedence:** omp is a multi-provider harness: capability providers `native` (`.omp`, priority 100) > `omp-plugins` (90) > `claude` (80) > `agents`/`codex`/`claude-plugins` (70) > `gemini` (60) > `opencode` (55) > `github` (30) > `agents-md` (10). Dedup per capability key, first-wins. Project `.omp` precedes user `~/.omp/agent`. For top-level files (`AGENTS.md`, `RULES.md`, `SYSTEM.md`) the native provider walks from cwd toward the repo root and uses only the **nearest non-empty** `.omp/` dir — no fallthrough to farther `.omp` dirs. Generic source-priority list also scans `.claude`, `.codex`, `.gemini` roots. (docs/config-usage.md, docs/context-files.md)

## Instructions file
- **Filenames:** `.omp/AGENTS.md` (project, nearest non-empty `.omp/` only) and `~/.omp/agent/AGENTS.md` (user). (docs/context-files.md)
- No required heading/title convention; content is injected verbatim into a `<repo-rules><file path="...">…</file></repo-rules>` block.
- **Import syntax:** `@path` tokens expand inline (relative to the importing file; `~` supported; code spans/fences untouched; `git@`/email tokens ignored; trailing punctuation trimmed; recursion max 5 hops; cycles skipped; missing targets left literal). (docs/context-files.md)
- Related top-level files: `RULES.md` (sticky always-apply rule), `SYSTEM.md` / `APPEND_SYSTEM.md` (system-prompt override), `TITLE_SYSTEM.md` (session-title prompt). omp also reads foreign instructions (`.claude/CLAUDE.md`, `.codex/AGENTS.md`, `.gemini/GEMINI.md`, `.github/copilot-instructions.md`, standalone `AGENTS.md`, `.agent[s]/AGENTS.md`) with one-user-file and one-project-file-per-depth shadowing. (docs/context-files.md)

## Skills
- **Supported.** Dirs: `<ancestor>/.omp/skills/<skill-name>/SKILL.md` (ancestors walked cwd→repo root), `~/.omp/agent/skills/<skill-name>/SKILL.md`, plus `skills.customDirectories`. (docs/skills.md, docs/config-usage.md)
- **Layout:** strictly non-recursive, one level: `<skills-root>/<name>/SKILL.md`; nested `<root>/group/<name>/SKILL.md` is NOT discovered. Assets live beside `SKILL.md`, reachable via `skill://<name>/<relpath>`. (docs/skills.md)
- **Exact frontmatter keys:** `name?` (defaults to directory name), `description?` (REQUIRED for native `.omp` provider, plugin, `github` provider, and custom dirs), `globs?: string[]`, `alwaysApply?: boolean`, `hide?: boolean` (hide from prompt list but still invocable), `disableModelInvocation?: boolean` (kebab-case `disable-model-invocation` normalized). **Unknown keys are preserved as metadata** (unlike Claude, where unknown keys may error). (docs/skills.md)
- **omp-unique keys:** `hide`, `disableModelInvocation`, `globs`, `alwaysApply`. **Not present:** Claude's `allowed-tools` — there is no per-skill tool allowlist key.
- **Limits:** no documented name/size limit; name matching is exact and dedup is by name, first-wins by provider priority. Interactive invocation via `/skill:<name>` when `skills.enableSkillCommands` is on.

## Hooks
- **Supported, but as JS/TS code modules, not declarative JSON.** Discovered from `.omp/hooks/pre/*` and `.omp/hooks/post/*` (and user equivalents); `--hook` is an alias for `--extension`. Each file default-exports a factory `(pi: HookAPI) => void` that registers handlers via `pi.on(event, handler)`. `HookAPI` is legacy; `ExtensionAPI` is preferred. (docs/hooks.md, docs/config-usage.md, docs/skills/authoring-hooks.md)
- **Config file/format:** none — no hooks section in `config.yml`; hooks are `.ts`/`.js` files.
- **Event names (snake_case, NOT Claude's PascalCase):** `tool_call`, `tool_result`, `session_start`, `session_before_switch`, `session_switch`, `session_before_branch`, `session_branch`, `session_before_compact`, `session.compacting` (note the dot), `session_compact`, `session_before_tree`, `session_tree`, `session_shutdown`, `context`, `before_agent_start`, `agent_start`, `agent_end`, `turn_start`, `turn_end`, `auto_compaction_start/end`, `auto_retry_start/end`, `ttsr_triggered`, `todo_reminder`. Extension-only: `tool_execution_start/update/end`, `input`, `user_bash`, `user_python`. (docs/hooks.md, docs/skills/authoring-hooks.md)
- **Matcher schema:** none — handlers receive `event.toolName`, `event.input`, `event.toolCallId` and match in code.
- **Command schema / stdin JSON envelope:** N/A. Hooks run in-process with a `ctx` object (`hasUI`, `cwd`, `sessionManager`, `ui.*`, `model`, `abort()`, …); there is NO stdin JSON envelope and NO stdout protocol (unlike Claude/Codex shell hooks).
- **Output contract (handler return values):** `tool_call` → `{ block?, reason?, input? }` (first block short-circuits; `input` replaces raw tool args, ignored for `computer`); `tool_result` → `{ content?, details?, isError? }` (last override wins; `isError` not applied on success path); `context` → `{ messages? }` (chained); `before_agent_start` → `{ message? }` (first wins); `session_before_*` → `{ cancel?, … }`. Handler throws on `tool_call` fail closed (tool blocked). (docs/hooks.md)

## Subagents
- **Dirs:** project `.omp/agents/*.md`, user `~/.omp/agent/agents/*.md`, plus extension/plugin `agents/` dirs. Cross-harness `.claude/agents` etc. are intentionally skipped. (docs/task-agent-discovery.md)
- **Format:** Markdown with YAML frontmatter; body is the system prompt (`systemPrompt` required in the normalized `AgentDefinition`).
- **Frontmatter:** `name` and `description` REQUIRED (missing ⇒ file skipped with warning). Optional: `tools` (CSV or array; `yield` auto-added), `spawns` (`*`, CSV, or array; defaults to `*` when `tools` includes `task`), `model` (selector, CSV, or prioritized array; `@role` aliases via `modelRoles`), `thinking-level`/`thinking` (normalized `thinkingLevel`), `output` (opaque output schema), `blocking`, `autoloadSkills` (skill names injected into child), `read-summarize` (→ `readSummarize`; `false` forces verbatim reads), `prewalk` (`true` or model string). (docs/task-agent-discovery.md)
- Dedup: first-wins by exact case-sensitive `name`; project beats user beats extensions beats bundled.

## Commands
- **Dirs:** project `<cwd>/.omp/commands/*.md`, user `~/.omp/agent/commands/*.md` (non-recursive, `*.md` only, hidden files skipped); project beats user on name collision. (docs/slash-command-internals.md)
- **Format:** Markdown; optional frontmatter `description` (else first body line, max 60 chars) and `name` override (filename otherwise). Body is a template with `$1`, `$2`, `$@[start]`, `$@[start:length]`, `$ARGUMENTS`, `$@` placeholders; unmatched args appended. Unknown `/x` falls through as literal prompt text (never rejected). Also discovers `.claude/commands/**` (recursive, namespaced `dir:cmd`), `.codex/commands/*.md`, `.opencode/commands/*.md`, `.agent[s]/commands/*.md`.

## Rules
- **Distinct from instructions — yes.** Dirs: `.omp/rules/*.{md,mdc}` (project), `~/.omp/agent/rules/*.{md,mdc}` (user), plus sticky top-level `RULES.md` (synthesized as rule name `RULES`, forced `alwaysApply: true`, frontmatter cannot un-stick it). (docs/rulebook-matching-pipeline.md, docs/context-files.md)
- **Format:** Markdown, name = filename minus extension; frontmatter keys: `description`, `globs`, `alwaysApply`, `condition` (regex TTSR trigger; legacy `ttsr_trigger` accepted), `astCondition` (ast-grep patterns), `scope` (`text`/`thinking`/`tool`/`tool:<name>(<glob>)`), `interruptMode` (`never|prose-only|tool-only|always`). Kebab-case keys normalized to camelCase. Bucketing: `condition`/`astCondition` → TTSR-only; else `alwaysApply: true` → injected into system prompt; else needs `description` to appear in the rulebook (`rule://<name>`). A rule with none of these is undiscoverable.

## MCP
- **Config files:** project `.omp/mcp.json` then `.omp/.mcp.json`; user `~/.omp/agent/mcp.json` then `.mcp.json` (profile-scoped); fallback root `mcp.json`/`.mcp.json`. Also imports `.claude/.mcp.json`, `~/.claude.json`, `.codex/config.toml`, `.gemini/settings.json`, `opencode.json`, `.cursor/mcp.json`, `.windsurf/mcp_config.json`, `.vscode/mcp.json`. (docs/mcp-config.md)
- **Format/shape:** JSON, `$schema` URL optional. Top level: `mcpServers` map, `disabledServers[]`, `enabledServers[]`. Server fields: `type: "stdio"|"http"|"sse"` (default `stdio`); stdio: `command` (req), `args`, `env`, `cwd`; http/sse: `url` (req), `headers`; shared: `enabled`, `timeout` (ms, 0 disables; `OMP_MCP_TIMEOUT_MS` overrides), `requestIdFormat: "number"|"string"` (**OMP-specific, ignored for imported foreign configs**), `auth{}`, `oauth{}`. Validation: not both `command` and `url`; unknown `type` rejected. Names ≤100 chars, `[A-Za-z0-9_\-.:]` (schema omits `:` — known mismatch).
- **Env handling:** `${VAR}` / `${VAR:-default}` expanded at discovery (recursive, unresolved left literal); pre-connect, an `env`/`headers` value starting with `!` runs as a shell command (10s timeout, cached); a value exactly naming an env var copies that var; otherwise literal. (docs/mcp-config.md)

## Translation hazards
1. **Instructions heading convention is moot** — omp injects raw content; no title normalization needed, but `@import` paths resolve relative to the importing file, so a canonical store that relocates files breaks relative `@` imports.
2. **Nearest-non-empty `.omp/` only** for project `AGENTS.md`/`RULES.md`: materializing an `.omp/` dir containing ONLY a skills subdir makes it "non-empty" and can shadow a farther `.omp/AGENTS.md` — agentlink must not create stray non-empty `.omp/` dirs. (docs/context-files.md)
3. **User dir is `~/.omp/agent/`, not `~/.omp/`** — the mapping `.omp/skills → .agents/skills` needs the extra `agent/` segment at user scope (and profile awareness).
4. **Skills:** drop Claude-only `allowed-tools`, `license`, `metadata` (omp preserves unknown keys harmlessly, but `allowed-tools` has no effect); rename kebab `disable-model-invocation` works (normalized); **ensure `description` exists — native provider refuses skills without one** (hard failure vs Claude's leniency). Layout must be flattened to one level (`skills/<name>/SKILL.md`); nested skill dirs are silently undiscovered. No `name` size limit documented.
5. **Hooks are untranslatable from declarative configs:** no JSON hook config, no `PreToolUse`/`PostToolUse` events, no matcher blocks, no shell-command hooks, no stdin JSON envelope. Claude `PreToolUse` ≈ `tool_call`, `PostToolUse` ≈ `tool_result`, `SessionStart` ≈ `session_start`, `UserPromptSubmit`/`Notification`/`Stop` have no direct equivalent; `agentlink guard`/`remind` shell-hook envelopes (Claude `file_path` / Codex `PostToolUse` JSON) CANNOT be expressed as omp hooks — they'd need to become TS factory modules calling `pi.exec`. Canonical stores must either drop hooks for omp or synthesize TS modules.
6. **Subagents:** cross-harness `.claude/agents/*.md` frontmatter is explicitly NOT compatible (`TASK_AGENT_CONFIG_SOURCE = ".omp"` filter) — must copy into `.omp/agents/*.md` and rename keys: Claude's `tools` CSV works, but `model` accepts omp selector/`@role` syntax; omp-only keys (`spawns`, `prewalk`, `autoloadSkills`, `read-summarize`, `thinking-level`, `blocking`, `output`) must be dropped when targeting other agents. `name`+`description` required; case-sensitive.
7. **Commands:** non-recursive only — Claude-style `commands/foo/bar.md` namespaced commands must be flattened (omp won't scan subdirs); template placeholders are `$1`/`$ARGUMENTS`/`$@` (Claude-compatible), but no frontmatter `allowed-tools`/`argument-hint` semantics documented — drop them.
8. **Rules:** `.md` or `.mdc` both fine; Cursor `alwaysApply`/`globs`/`description` map directly; GitHub `applyTo` is normalized (`*`/`**`/`**/*` → alwaysApply). omp-only keys to drop for other targets: `condition`, `astCondition`, `scope`, `interruptMode`, `ttsr_trigger`. A rule with neither `description`, `alwaysApply`, nor a TTSR condition is dead — canonical rules must carry `description` or `alwaysApply: true`.
9. **MCP:** JSON `mcpServers` shape is Claude-compatible, but drop OMP-only `requestIdFormat` for other targets; beware `!command` env indirection and bare-env-var-name passthrough are omp-specific resolution semantics — other tools would treat them literally; `disabledServers`/`enabledServers` top-level keys are omp-specific; `${VAR:-default}` expansion is omp-side (safe to emit); server names may contain `:` but the bundled schema rejects it — avoid `:` in canonical names.
10. **Provider shadowing:** because `native` outranks everything, any `.omp/` artifact agentlink writes shadows the equivalent `.claude`/`.codex` content at the same scope/depth — syncing into `.omp/` is authoritative; stale duplicates in `.omp/` silently win over edited `.claude` files. `disabledProviders: [native]` is the only off switch (config.yml).
11. **Frontmatter parsing leniency:** on YAML failure omp falls back to `key: value` line parsing — multiline/nested YAML structures (arrays in block style, objects) can be silently mangled; canonical emitters should use flow-style single-line values for safety. (docs/rulebook-matching-pipeline.md §3)
